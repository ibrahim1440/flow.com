## 5. Production runbook (to execute once permitted)

Operator machine: a checkout of the release branch; only the production **owner** URL in the
shell as `DIRECT_URL`/`DATABASE_URL` for step 3 (never a repo `.env`).

1. **Freeze.** Announce a short write pause (no ERP entries) for the migration window.
2. **Backup.** Neon: create branch `backup-pre-finance-sales-<UTC timestamp>` from
   `br-weathered-bread-aqais7hp`; record its id and LSN; mark it protected. This is the recovery point.
3. **Rehearse on a copy (external effects off).** Branch `rehearsal-finance-sales-<ts>` from the same
   parent with its own compute; run `npm run db:migrate:deploy` against it; post-checks
   (`migrate status`, empty `migrate diff`, 12 triggers, row counts of existing tables unchanged);
   run the production build (`4640cbe`) client read check (`old-client-compat`); create the
   runtime role there (step 5 SQL) and run the application locally against the copy **as that
   role** (no fixture, no seed, read-only smoke + one dry navigation per role). Delete the copy.
4. **Migrate production.** `npm run db:migrate:deploy` with the owner URL; confirm the printed host
   is `ep-dawn-dust-aqn1u1uf`; post-checks as in 3; smoke www.beanflow.net (still `4640cbe`).
5. **Restricted runtime role.** On production:
   `CREATE ROLE erp_app LOGIN PASSWORD '<generated>' NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS;`
   `GRANT CONNECT ON DATABASE neondb TO erp_app; GRANT USAGE ON SCHEMA public TO erp_app;`
   `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO erp_app;`
   `GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO erp_app;`
   `REVOKE TRUNCATE, TRIGGER, REFERENCES ON ALL TABLES IN SCHEMA public FROM erp_app;`
   `ALTER DEFAULT PRIVILEGES FOR ROLE neondb_owner IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO erp_app;`
   `ALTER DEFAULT PRIVILEGES FOR ROLE neondb_owner IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO erp_app;`
   Verify from a session as `erp_app`: TRUNCATE, DISABLE TRIGGER, DDL refused; reads/writes work.
   Update Vercel **production** `DATABASE_URL` (sensitive) to the pooled URL for `erp_app`; keep the
   owner URL out of Vercel runtime.
6. **Merge.** Merge the PR into `main` (merge commit) → production deployment builds with the new
   `DATABASE_URL`. Wait for READY; confirm the deployment's commit is the merge commit.
7. **Verify live.** Login page, dashboard, orders, inventory, Sales, Finance for an administrator and
